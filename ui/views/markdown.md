# Markdown

Публичный компонент: `@zavx0z/ui/views/markdown`.

`Markdown` принимает `source`, необязательные `wrap`, `baseUrl`, `title` и `style`.
Он создаёт один `<article>` в Document вызывающего приложения. Размер области
задаётся через `style`; по умолчанию документ занимает доступную ширину.
Цвета берутся из общей UI theme. Компонент можно вложить в Pane, Display или HUD.

`wrap` по умолчанию равен `true`: обычный текст запрашивает перенос по ширине
через `white-space: normal`. `wrap={false}` задаёт `white-space: nowrap`.
Блоки кода сохраняют собственную прокрутку и режим сохранения пробелов.
Renderer переносит текст и вложенные inline-элементы по общим строкам абзаца,
сохраняя семантические узлы, цвета и области попадания. Переключение `wrap`
пересчитывает раскладку того же article.

Общий парсер `@zavx0z/ui/markdown` использует markdown-it (CommonMark) и parse5.
Storybook использует тот же разбор для списка разрешённых ресурсов README;
UI не зависит от Storybook. Storybook импортирует публичный
Markdown и отдельно компонует свою overview action. Блоки кода используют
существующий `CodeEditor` и его Highlighter. Изменение `source` или `baseUrl`
обновляет содержимое с сохранением корневого article.
`baseUrl` может быть абсолютным URL или путём от корня сайта. Относительные
картинки и ссылки разрешаются относительно него с сохранением query и fragment.

Блок кода использует `height: auto`: высота определяется реальными строками и
отступами CodeEditor. Его колонка номеров не сжимается, область кода занимает
оставшуюся ширину. Прокрутка принадлежит общему Renderer и появляется только
при переполнении. Для отдельного CodeEditor фиксированный viewport по-прежнему
задаётся через `style`; отдельный параметр автоматической высоты не требуется.
Подробности размеров и регрессионное воспроизведение flex minimum находятся
в [CodeEditor](code-editor.md).

## Поддерживаемый синтаксис

- ATX-заголовки `#`–`######` с настоящими `<h1>`–`<h6>`.
- Абзацы, вложенные списки и цитаты, горизонтальные разделители.
- Жирное и курсивное выделение, вложенный inline-код, в том числе внутри ссылок.
- CommonMark-ссылки и изображения, fenced и indented code blocks.
- Безопасные HTML div/span, выделение, ссылки, img и br преобразуются в semantic
  элементы. Учитываются src, alt, title, width/height и align для div.
- Script, iframe и неизвестные HTML-элементы остаются текстом; обработчики событий
  и произвольные HTML styles не переносятся. Исполняемые URL не становятся ссылками.

GFM-таблицы и task lists не включены. Компонент сам не выполняет переходы по
ссылкам и не реализует выделение обычного текста. GIF воспроизводится общим
WebGPU texture loader через браузерный ImageDecoder с задержками и повторениями
из файла. В браузере без GIF ImageDecoder остаётся статичный кадр с диагностикой.
Полностью вышедший за viewport/clips GIF приостанавливается общим WebGPU
загрузчиком. При возвращении он продолжает с сохранённой позиции; видимая
копия той же текстуры удерживает её анимацию активной.

## Проверка и ограничения платформы

`ui/tests/markdown.test.ts` проверяет разбор, семантику, обновление, cleanup и
переиспользование CodeEditor. Storybook показывает основной пример по маршруту
`components/data/markdown/basic/default`.

Сравнение режимов: `MarkdownWrappingFixture` в `ui/views/markdown.fixture.tsx`,
маршруты `components/data/markdown/rendering/wrapping` и
`components/data/markdown/rendering/no-wrap`.

Абзац с inline code переносится по словам внутри ширины 180 px. При `wrap=false`
он остаётся одной строкой с горизонтальным переполнением. Общие поведенческие
проверки принадлежат Renderer: `renderer/tests/inline-flow.test.ts`. Длинные слова
без разрешённых пробелов остаются неразрывными и могут переполнять область.

Renderer и WebGPU выбирают один и тот же зарегистрированный font face для
измерения и рисования. `createExperience` принимает готовые `fontFaces` либо
декларации `fontSources` для загрузки через общий font cache. Storybook объявляет
Inter и JetBrains Mono из Engine-owned assets. Естественные размеры
изображений поступают в Renderer из существующего WebGPU texture loader.
Маркеры `<ul>/<ol>` ещё требуют общего Renderer behavior. Обычные `href` требуют платформенного поведения
ссылок для навигации. Эти ограничения не компенсируются локальной раскладкой,
рисованием или диспетчером событий.
