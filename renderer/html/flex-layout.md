# Размеры flex-строк

Renderer рассчитывает flex-геометрию на CPU по одному semantic Document.
Полученные боксы служат общей основой для рисования, hit testing, выделения и
прокрутки. WebGPU получает готовые записи кадра; компонент не измеряет текст,
не назначает высоты строк и не запускает отдельный цикл раскладки.

Для горизонтальной flex-строки порядок расчёта такой:

1. Собрать участвующих детей и распределить их по строкам с учётом basis,
   margins, gap и flex-wrap.
2. Вычислить фактическую ширину каждого элемента через общий grow/shrink и
   ограничения min/max.
3. Измерить содержимое на этой ширине. Padding и border вычитаются из итогового
   border box; вложенные проценты получают ширину своего содержащего блока.
4. Выбрать высоту строки по максимальной внешней высоте её элементов. Учесть
   align-items, align-content, ограничения контейнера и расположить элементы.

Этот порядок соответствует [CSS Flexbox, определение поперечного размера](https://www.w3.org/TR/css-flexbox-1/#cross-sizing).
Измерение до grow/shrink не определяет высоту готовой строки: после сужения
элемента текст переносится, а изображение с естественными пропорциями меняет
высоту. Явные height/max-height сохраняют свою роль и могут создавать overflow.

## Единый расчёт и повторное использование

`resolvedFlexLines` используется при измерении горизонтального контейнера и
при размещении flex-детей. Результат содержит индексы элементов, окончательные
главные размеры, измеренные поперечные размеры и размеры строк. Он не содержит
экранных координат, DOM-копий или GPU-объектов. `intrinsicHeight` горизонтального
контейнера получает высоту из этого же измерения, в том числе когда контейнер
является элементом вертикального flex-контейнера.

Доступная ширина и фактическая ширина flex-элемента — разные ограничения.
`measure` принимает фактическую ширину отдельно: исходное width, в том числе
процентное, не должно отменять уже вычисленные grow/shrink. Ключ кэша различает
измерение свободного элемента и измерение при назначенной ширине.

Планы строк хранятся в WeakMap по LayoutNode и размерам доступного содержимого,
не более восьми вариантов на узел, как и существующие кэши измерений и inline
планов. Они используют тот же жизненный цикл: обновлённые layout-узлы получают
новые записи, общий сброс измерений сбрасывает и flex-планы. Чистый `flush`
возвращает прежний кадр. Быстрые пути прокрутки и transform продолжают работать
с готовой геометрией, без нового измерения текста.

Распределение свободного пространства сохраняет существующий алгоритм
grow/shrink; срез не объявляет полный CSS Flexbox реализованным. В частности,
новые baseline/align-self и intrinsic sizing режимы здесь не вводятся.

## Проверки

`tests/flex-cross-size.test.ts` проверяет разные выравнивания, назначенную ширину
после shrink, несколько flex-строк, вложенные row/column, проценты, изображения,
ограниченную высоту, resize, изменение текста и повторное использование чистого
кадра. Общие проверки streaming, scroll и transform защищают существующее
поведение кэшей. `ui/tests/markdown.test.ts` проверяет отсутствие наложения
длинного текста в настоящей таблице Markdown; живое воспроизведение — README
`@nodes/layout` и основной пример Markdown в UI.
