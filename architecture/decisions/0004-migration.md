## Решение

Перенос истории, смена имени, объединение пакетов и изменение архитектуры
выполняются отдельными проверяемыми срезами. Ни один срез не удаляет прежнего
владельца до доказательства сохранности его поведения.

Исходные checkout в `projects/` и соседние Renderer/Template уже являются
сохраняемыми источниками истории. Дополнительные копии и worktree не создаются.

## Обязательный порядок

1. Записать принятые решения.
2. Разобрать уже существующие незавершённые изменения.
3. Зафиксировать соответствие прежних и новых владельцев.
4. Проверить уже выполненный history-preserving import.
5. Закончить только физическое размещение файлов.
6. Отдельно менять package names и все прямые imports.
7. Отдельно объединять прежние package contracts.
8. Только после сохранения прежнего поведения реализовывать новые `space`
   capabilities.

## Условия каждого среза

- заранее указан точный список затрагиваемых владельцев;
- отсутствуют необъяснённые удаления;
- все прежние public exports и consumers учтены;
- проверки владельца и непосредственных потребителей проходят;
- для видимого поведения сохранены exact route, interaction и визуальная
  приёмка;
- capability evidence указывает на точный коммит реализации;
- в каждый момент существует ровно один writable owner;
- push выполняется только по отдельному указанию.

## Урок DOM-миграции

Тесты, готовность страницы, пустая консоль и непустое изображение доказывают
только механику запуска. Они не доказывают сохранение состава, геометрии,
материалов, взаимодействия, identity, ресурсов и производительности. Прежний
владелец сохраняется до полного доказательства и явного решения владельца.
