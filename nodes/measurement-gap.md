# Измерение графа до показа

Общий GraphView и GraphEditor используют одну реализацию отображения принятой
числовой сцены. Это не завершённый автоматический цикл CSS-измерения графа.

## Ожидаемое поведение

Просмотр создаёт реальные элементы в Document текущего Experience, получает
их размеры и позиции точек подключения в локальных CSS-координатах, вызывает
числовой Layout и показывает принятую геометрию. Элементы сохраняют identity.
Pan/zoom и пространственная проекция не меняют размеры, передаваемые Layout.
Текст, flex, padding, border, шрифт и ограничения ширины учитываются платформой.

## Наблюдаемое ограничение

`Element.getBoundingClientRect()` уже синхронно обновляет CPU layout до
GPU-показа. Но результат включает CSS transforms и Browser projection.
Это правильная экранная семантика метода, не ошибка его реализации.
В публичном DOM нет `offsetWidth`/`offsetHeight`; в проверенном авторском API
нет общего получения дробной border-box/anchor geometry до проекции и
согласованного уведомления об изменении такой геометрии.

[graph.test.ts](view/tests/graph.test.ts), `GRAPH-MEASUREMENT-GAP-001`, создаёт
реальный TSX с intrinsic flex-размером. Тот же скрытый элемент без GPU:

1. Возвращает ненулевой client rect при единичной проекции.
2. При удвоении проекции возвращает удвоенный размер, хотя локальный CSS box
   остаётся прежним.
3. После изменения текста возвращает новую геометрию без remount.

`RenderFrame.boxByNode` используется исключительно как тестовый oracle.
Production Nodes не получает объект Renderer и не читает его состояние.

Отдельная компонентная граница: действующие конкретные ноды принимают готовый
`rect` и задают по нему размеры до mount. Для автоматического измерения нужен
честный режим подготовки тех же элементов по CSS без заранее вычисленного
размера. Нельзя измерить заданную константу и назвать её intrinsic-размером.

## Владельцы следующего среза

- DOM и HTML Renderer: публичная локальная геометрия и её актуальность.
- Browser: подключение геометрии к существующим projection/frame lifecycle.
- Nodes: подготовка тех же элементов, измерение через публичный договор,
  source/content/presentation/font/constraints generation, запуск Layout и
  принятие результата до показа.
- Layout: только числовые размеры, положения и маршруты.

Capability ID нового контракта не назначался. Platform owners в этой миграции
не менялись. Generic изменение требует отдельного поручения правильному owner.

## Что сохранено до закрытия ограничения

Готовая геометрия и source-bound `createNodeTreeLayout` продолжают работать.
GraphView принимает ортогональные и cubic маршруты через существующий Link.
Адаптер модели сохраняет собственную WEST/EAST socket-валидацию; он не выдаёт
её за полную поддержку вертикальных сокетов.

Mermaid теперь использует GraphView вместо отдельного renderer-компонента.
Его прежний числовой план в `markdown/mermaid/src/layout.ts` всё ещё содержит
заданные размеры. Они не добавлены как обход и не объявлены измерением.
Measured Mermaid, автоматические font/theme/content invalidation и точное
совпадение с эталоном Codex остаются незавершёнными. Ошибка платформы не
маскируется новым CSS parser, второй моделью/Canvas или сменой ожидаемых размеров.
