# Нодовая система

Production-компоненты показывают один живой NodeTree: параметры, сокеты, связи,
рамки и редактор. Состояние значений принадлежит `@nodes/tree`, числовая
раскладка — `@nodes/layout`, универсальные поля — `@zavx0z/ui`.

## Каталог

- **Сокеты** — все 19 видов, восемь форм, вход/выход/двунаправленный endpoint,
  выбор, подключённость, недоступность и строковое представление.
- **Параметры** — 15 механизмов. У каждого есть прямой production-компонент,
  варианты сокетов слева/справа/с двух сторон, подключение, состояния и проекция
  из реального Parameter Store. Matrix, Vector и Collection отдельно показывают
  размеры. Значение и revision видны под примером.
- **Компоненты** — Node, Frame, Link, NodeTree и NodeEditor. Примеры показывают
  composition, selection/collapse/preview, внешнее состояние, изменения Store,
  отсечение и управляемую навигацию. Вариант добавления ноды проверяет
  согласованное обновление topology и Layout с сохранением identity.
- **Раскладка** — сохранённые шесть примеров Fixed/Adaptive: горизонтальная и
  вертикальная форма области, общий Socket и составные Frame.

Щелчок по сокету показывает activation, кнопки примеров изменяют настоящее
состояние. Path/Collection демонстрируют запросы действий к приложению; эти
callbacks не открывают файловую систему и не изображают готовый domain editor.

Каждая история монтирует существующие публичные TSX в Display, предоставленный
Storybook. Её source и стили относятся к тем же production-компонентам.
Общие обзоры собирают те же истории и вписывают их в отдельные карточки.

## Границы

Перетаскивание ноды и создание связей жестом ещё не входят в текущий NodeEditor.
TopDown/Coffman–Graham показаны как числовые алгоритмы у Layout; их полная
интеграция с NodeEditor требует договора верхних/нижних сокетов.

NodeType остаётся отдельным будущим production-срезом. Нынешний NodeTemplate
содержит сохраняемую идентичность; каталог не выдаёт его за готовую декларацию
состава и defaults.

`components/node-tree/topology` показывает согласованное обновление модели
и раскладки. Для асинхронного расчёта `createNodeTreeLayout(store, compute)`
связывает geometry с исходным snapshot и отвергает устаревший результат.
Во время ожидания старый ввод блокируется, уцелевшие Elements сохраняются.
[Договор и проверки](topology-layout-gap.md) также описывают отдельное
ограничение Layout для несвязанных портов.

## Проверки

[Матрица покрытия](storybook-coverage.md) связывает возможности, исходники,
проверки и маршруты. Каталог проверяется по публичным видам Socket и всем
Parameter-механизмам; новые примеры проходят компиляцию, монтирование, ввод и
cleanup. Успех unit tests дополняется живой проверкой Storybook MCP.
