# Физический дисплей

`display` является базовым пространственно-интерфейсным элементом общего
Document. DOM владеет его identity, детьми, событиями, фокусом и прокруткой.
Renderer вычисляет CSS и раскладку; Browser связывает поверхность с общим
пространством; WebGPU рисует её конечную пиксельную матрицу в том же Renderer.

## Авторский контракт

Три независимые характеристики задаются только CSS:

* `width` и `height` — конечные положительные физические размеры поверхности;
* `resolution` — плотность матрицы, положительное значение в `dpi`, `dpcm`,
  `dppx` или `x`; по умолчанию `96dpi`.

Свойство `resolution` является расширением платформы со стандартной CSS-грамматикой
плотности. Размеры поддерживают абсолютные CSS-единицы `mm`, `cm`, `Q`, `in`,
`pt`, `pc`, `px` и совместимые вычисления `calc`. Один CSS px равен `25.4/96` мм.
Процентные размеры поверхности в первом этапе не поддерживаются: отсутствует
содержащий её двумерный viewport с физическими габаритами.

Размер матрицы выводится по каждой оси как округлённое до ближайшего целого
произведение CSS-размера на `resolution/96`, минимум один пиксель. Округление
не меняет физический габарит. Номинальная плотность и конечная матрица поэтому
могут незначительно различаться для размеров, не кратных шагу пикселя.
Квадратные пиксели являются исходной моделью; субпиксели LED, зазоры и яркость
не моделируются в этом этапе. Размер матрицы, превышающий предел GPU,
отклоняется явно и не заменяется меньшей матрицей молча.

## Положение и содержимое

Начало координат поверхности находится в её центре; нулевая ориентация — XY.
`translate`, `rotate`, `scale` используют стандартную грамматику отдельных
трансформаций и правую мировую систему Z-up. Длины переводятся в миллиметры,
углы принимают `deg`, `rad`, `grad`, `turn`. `transform-origin` задаёт опорную
точку, по умолчанию центр. Нулевой масштаб отклоняется: обратная проекция ввода
должна оставаться определённой. Составной `transform` будет отдельным этапом;
сейчас ненулевое значение этого свойства на display отклоняется явно.

В этом этапе display является непосредственным ребёнком Space. Вложенные
display и перенос самой поверхности между пространственными родителями пока
не поддерживаются. Перенос обычных UI-детей между проекциями того же Document
сохраняет их identity, события и состояние.

Внутри поверхности действуют обычные block/flex-раскладка, цвета, рамки,
типографика, padding и overflow. В этом этапе используется border-box:
физический габарит включает рамку и padding. Явный content-box пока отклоняется. Прокрутка меняет содержимое,
а пространственная трансформация — положение всей поверхности. Видимость
поверхности следует `display: none` и `visibility: hidden`.

Повышение плотности улучшает детализацию, сохраняя размер поверхности и
физический масштаб интерфейса. Изменение окна и камеры не меняет эти
характеристики. Matrix рисуется в GPU-текстуру, затем отображается на
поверхности; при приближении наблюдаются именно её пиксели. Canvas, Document,
Space, ViewPoint и ввод остаются общими. Внутренняя растровая проекция не
создаёт независимую камеру приложения.

## Вычисленные факты

Свойства Element `viewport`, `pixelWidth`, `pixelHeight`, `resolution` доступны
только для чтения после подготовки проекции. `viewport` — область раскладки в
CSS px, `pixelWidth/Height` — матрица, `resolution` — номинальная плотность в dpi.
При изменении этих фактов элемент отправляет `resize` после текущего commit.
Дети, которым нужны числовые размеры для собственного layout-плана, читают
вычисленный viewport; они не повторяют перевод физических единиц.

Первый этап не удаляет старый компонент Display у остальных потребителей.
Границу действующих пространственных компонентов сохраняет
[контракт Space](../space/README.md).
