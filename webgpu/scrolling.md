# GPU-ресурсы при прокрутке

Прокрутка использует общий retained backend и тот же Document, Canvas и Renderer.
Подготовка видимого окна описана в [Renderer](../renderer/html/scrolling.md).
Следующие механизмы не зависят от CodeEditor, Markdown или Storybook.

## Общая геометрия прямоугольников

Scalar rectangles одного backend с одинаковыми точными размерами используют
одну PlaneGeometry и её GPU-буферы. Цвет, скругление, границы, clipping, opacity
и положение остаются у отдельного материала/объекта. Для теней ключ содержит
размер расширенной плоскости, поэтому тень не обрезается до размеров тела.

Изменение размера получает другую плоскость, сохраняя геометрию остальных
владельцев. Удаление и dispose освобождают GPU-буферы только после последнего
владельца. Image planes и текстовая геометрия этим механизмом не изменяются.

Контрольный прогон production CodeEditor с 420 HTML-строками до и после
объединения плоскостей:

| Шаг | Создано GPUBuffer до | После |
| --- | ---: | ---: |
| Первый видимый кадр | 536 | 176 |
| Вход в следующие строки | 44 | 8 |
| Возврат к уже показанным строкам | 0 | 0 |
| Вход в новый участок по X | 92 | 48 |

Это вызовы production geometry-upload path с тестовым GPUDevice, не время GPU
и не FPS. Оставшиеся создания относятся, в частности, к впервые видимой
текстовой геометрии. Нулевая аллокация для всех новых глифов не заявляется.

Воспроизводимая регрессия:

```sh
bun test webgpu/tests/scalar-rect-geometry.test.ts
```

Она проверяет общие буферы, независимые материалы, resize, обе оси scroll,
возврат в видимую область, тени и освобождение после последнего владельца.

## Повторное выполнение команд

Renderer удерживает render bundle для точной последовательности команд слоя.
Первый и изменившийся набор команд исполняются напрямую. Bundle создаётся только
при повторении того же набора в следующем кадре. Непрерывно меняющийся слой
не создаёт новый GPU bundle на каждом scroll; проверка охватывает 1500 кадров.
Каждый кадр продолжает синхронизировать материалы, геометрию, transforms,
uniforms и clipping. Кеш сравнивает identity GPU-ресурсов и все числовые
аргументы, включая dynamic offsets, диапазоны буферов и параметры draw.
Изменение данных внутри прежнего буфера не требует новой последовательности;
замена ресурса, pipeline, порядка или диапазона рисования перестраивает bundle.

Кеш ограничен числом слоёв и размером последовательности. Удалённые слои
освобождаются, превышение лимита сохраняет прямое кодирование команд.
Viewport, scissor и stencil reference принадлежат текущему render pass.
Порядок прозрачных объектов и отдельный проход overlay lines сохраняются.

Это уменьшает повторную CPU-работу кодирования WebGPU-команд. Число исполняемых
GPU draw calls и стоимость шейдеров от самого reuse bundle не уменьшаются.
Неподвижный слой продолжает участвовать в композиции: его пиксели не кешируются
по предположению о неизменности DOM. Счётчик draw в захвате, который не раскрывает
executeBundles, нельзя интерпретировать как отсутствие рисования.

Для 1274 неизменных draws за 10 кадров контрольный encoder регистрирует 2548
native draw encodes вместо 12740: один прямой кадр и одно построение bundle.
Все 12740 GPU draws сохраняются. Проверки — `tests/render-bundle-cache.test.ts`.

## Сценарии Storybook

Визуальный стенд находится в UI → Редактор кода → Производительность:

- `components/data/code-editor/performance/large` — 420 HTML-строк, область 700×440.
- `components/data/code-editor/performance/compact` — тот же исходник,
  область 700×180 и подсказка заголовка.

Сценарии используют production CodeEditor и переданный Storybook Document.
Колесо и кнопки прокручивают настоящий semantic Element, соседняя панель
остаётся неподвижной. Display, Canvas и frame/input lifecycle принадлежат
общему Storybook Experience. Отдельные HTTP-сервер и приложение удалены.

Исходник: `ui/.storybook/stories/compiled/compiled-code-editor-scroll-story.tsx`.
Проверка: `bun test ui/tests/code-editor-scroll-story.test.ts`.
Инструменты CPU/GPU-профилирования должны измерять общий кадр Storybook;
сценарий не показывает исторические числа в качестве живого FPS.

## Исторический диагностический контроль, 2026-09-07

Следующие результаты получены до переноса визуального сценария в Storybook.
Сохранённые JSON — свидетельства того запуска, а не benchmark нынешнего
Workbench. Повторять измерения следует на указанных выше маршрутах.

Условия: Intel Mac, Chromium 152, видимая страница встроенного
браузера Codex без WebGPU Inspector, Canvas 1100×620, editor height 440.
Три цикла; в каждом 12 прогревочных и 30 измеряемых шагов на ось. Ниже агрегированы
все 90 измерений каждой оси. CPU и GPU измерялись отдельными сериями.

| Метрика | Y median / P95 | X median / P95 |
| --- | ---: | ---: |
| CPU: изменение scroll → возврат `Root.render()` | 8,70 / 18,20 ms | 7,90 / 10,80 ms |
| Интервал RAF в обычной CPU-серии | 16,70 / 33,30 ms | 16,60 / 17,40 ms |
| GPU: сумма обоих render passes | 1,049 / 2,490 ms | 1,049 / 1,835 ms |

CPU включает синхронную отправку WebGPU-команд, но не ожидание GPU. GPU-серия
ждёт readback между измерениями вне CPU timer, поэтому её RAF intervals
не являются FPS обычного приложения. GPU totals не включают очередь, uploads
и copy/readback. Все 360 render passes в 180 GPU-кадрах получили timestamps;
неполных samples нет. Validation/console errors в этом стенде не наблюдались.

Каждый цикл проверяет сохранение Node/key/kind, предыдущего immutable Frame
и геометрии соседней панели. В отдельном DPR 2 / height 180 / tooltip прогоне
эти проверки также прошли, подсказка добавила два overlay items.

Полные локальные данные окончательных серий:
[CPU](bench/dist/production-code-editor-browser/final-cpu.json) и
[GPU](bench/dist/production-code-editor-browser/final-gpu.json).
`bun run check` всего workspace завершился успешно.

Это стенд production-компонента, а не FPS полной страницы Nodes с её grid и
многочисленными соседними редакторами. Отдельные пропуски RAF остаются; постоянные
60 FPS не заявляются. На исходном Storybook route `layout/fixed/baseline/down`
обе оси HTML-редактора проверены визуально с неподвижными нодами. Повторная
активация Storybook сохраняет ранее наблюдавшийся timeout и два network 404
без URL в console projection; console-zero для этого view не заявляется.

Inspector capture `cap-1` содержал 4 submit, 8 passes, 16 writeBuffer (883040 B),
0 createBuffer и 0 validation errors. Удержанный base bundle выполнялся повторно.
Однако Inspector проставил timestamp только одному pass; его оценка `vsync`
и сумма 1,049 ms отвергнуты как неполные. Независимый benchmark-only измеритель
`production-code-editor-gpu-timing.ts` проверен на множественных submits,
повторном использовании readback, неподдерживаемых features и пропущенных passes:
неполный sample всегда возвращает `totalGpuMs: null`.
